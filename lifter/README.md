## Trace Lifter

The trace lifter processes execution traces collected from the modified VM script and lifts them into readable JavaScript code. It converts low-level bytecode operations into high-level JavaScript constructs.

## Overview

The lifter takes the comprehensive execution traces (typically 400+ MB) generated by the deobfuscator and performs a multi-stage transformation:

1. **Trace Parsing** - Loads and structures the raw execution data
2. **IR Generation** - Creates an intermediate representation with control flow
3. **JavaScript Lifting** - Converts IR to JavaScript AST
4. **Beautification** - Cleans and formats the output for readability

## Features

### Core Capabilities

- **Block Identification** - Identifies basic blocks based on jump instructions
- **Control Flow Translation** - Reconstructs if/else statements from bytecode branches
- **Function Reconstruction** - Rebuilds functions from execution traces
- **Code Cleaning** - Beautifies JavaScript output for readability
- **Variable Tracking** - Maintains stack variable relationships

### Advanced Features

- **Multi-version Function Support** - Handles multiple versions of the same function
- **Branch Deduplication** - Eliminates redundant execution paths
- **Stack State Management** - Accurately tracks stack operations
- **Global Object Resolution** - Resolves references to global objects

## How It Works

### Phase 1: Intermediate Representation (`ir.ts`)

The IR lifter processes raw execution traces:

1. **Parse Function Traces:**
   ```typescript
   // Input: Raw execution traces
   {
     "function_43518_9": [
       { "blockId": "104153_5", "operations": [...] }
     ]
   }
   ```

2. **Build Control Flow Graph:**
   - Identifies unique basic blocks
   - Maps jump relationships
   - Detects loops and conditionals

3. **Create IR Structure:**
   ```typescript
   // Output: Intermediate representation
   {
     functions: Map<string, IRFunction>
     blocks: Map<string, IRBlock>
     controlFlow: ControlFlowGraph
   }
   ```

### Phase 2: JavaScript Lifting (`lifter.ts`)

Converts IR to JavaScript AST:

1. **Function Generation:**
   - Creates function declarations
   - Initializes stack variables (s0, s1, s2, ...)
   - Sets up block structure

2. **Control Flow Reconstruction:**
   - Translates jumps into function calls between blocks
   - Generates if/else statements for conditionals
   - Preserves execution order

3. **Operation Translation:**
   - Stack operations → Variable assignments
   - Bytecode calls → JavaScript function calls
   - Global access → Property access expressions

### Phase 3: Traversal (`traverser.ts`)

The traverser walks the execution traces to:

- Identify all executed blocks
- Determine block entry/exit points
- Track variable dependencies
- Build the execution graph

### Phase 4: Beautification (`cleaner.ts`)

Cleans and formats the output:

1. **Code Simplification:**
   - Removes redundant assignments
   - Inlines single-use variables
   - Simplifies expressions

2. **Formatting:**
   - Proper indentation
   - Consistent spacing
   - Readable structure

## Usage

### Basic Usage

```bash
# 1. Place your vm_call_stack.json in the input/ directory
cp /path/to/vm_call_stack.json input/

# 2. Run the lifter
npm start

# 3. Check the output
cat cleaned.js
```

### Programmatic Usage

```javascript
import fs from 'fs';
import { IntermediateRepresentationLifter } from './ir';
import { JavascriptLifter } from './lifter';
import { JavascriptBeautifier } from './cleaner';
import { FunctionTrace } from './types';

// Step 1: Load execution traces
const functionTraces = JSON.parse(
  fs.readFileSync('input/vm_call_stack.json').toString()
);

// Step 2: Convert to Map structure
const functionTraceMap = new Map<string, FunctionTrace[]>();
Object.keys(functionTraces).forEach((key) => {
  functionTraceMap.set(key, functionTraces[key]);
});

// Step 3: Lift to Intermediate Representation
const irLifter = new IntermediateRepresentationLifter(functionTraceMap);
const ir = irLifter.lift();

// Step 4: Lift to JavaScript AST
const jsLifter = new JavascriptLifter(ir);
const outputAst = jsLifter.lift();

// Step 5: Clean and beautify
const cleaner = new JavascriptBeautifier(outputAst);
const cleanedCode = cleaner.clean();

// Step 6: Save output
fs.writeFileSync("cleaned.js", cleanedCode);
```

## Architecture

### Component Overview

```
vm_call_stack.json
       ↓
  [Traverser] ──→ Analyzes execution paths
       ↓
  [IR Lifter] ──→ Creates intermediate representation
       ↓
  [JS Lifter] ──→ Generates JavaScript AST
       ↓
  [Cleaner]   ──→ Beautifies output
       ↓
  cleaned.js
```

### Type Definitions (`types.d.ts`)

Key types used throughout the lifter:

```typescript
// Execution trace for a single function
interface FunctionTrace {
  blockId: string;
  operations: Operation[];
  nextBlock?: string;
}

// Individual operation in a trace
interface Operation {
  type: string;
  args?: any[];
  value?: any;
}
```

### Class Responsibilities

- **`IntermediateRepresentationLifter`** - Converts traces to IR
- **`JavascriptLifter`** - Converts IR to JavaScript AST  
- **`JavascriptBeautifier`** - Cleans and formats code
- **`TraceTraverser`** - Analyzes execution paths

### Known Limitations

⚠️ **Function Call Arguments:**
- Argument reconstruction is not fully accurate
- Arguments may be incomplete or incorrectly ordered
- **Recommendation:** Manually verify critical function calls

⚠️ **While Loops:**
- Not explicitly created in the output
- Loop behavior is represented through block calls
- **Example:**
  ```javascript
  // Instead of:
  while (condition) { body(); }
  
  // You get:
  function block_loop() {
    body();
    if (condition) block_loop(); // Recursive call
  }
  ```

⚠️ **Complex Control Flow:**
- Nested conditionals may be simplified
- Some edge cases might not lift perfectly
- **Recommendation:** Cross-reference with execution traces

⚠️ **Variable Names:**
- Stack variables use generic names (s0, s1, etc.)
- Original variable names are lost during virtualization
- **Recommendation:** Rename based on usage patterns

### Improving Output Quality

1. **Manual Review:**
   - Identify patterns in stack variable usage
   - Rename variables for clarity
   - Restructure loop representations

2. **Cross-Reference:**
   - Compare with execution traces
   - Verify critical operations
   - Check branch conditions

3. **Post-Processing:**
   - Use JavaScript minifiers/beautifiers
   - Apply custom refactoring scripts
   - Add comments for complex sections

## Troubleshooting

### Issue: "Out of memory" error

**Solution:**
```bash
# Increase heap size
node --max_old_space_size=8192 dist/index.js

# Or split trace files
# Process subsets of functions separately
```

### Issue: "Cannot find input/vm_call_stack.json"

**Solution:**
```bash
# Ensure the file exists
ls -lh input/vm_call_stack.json

# Check file path in index.ts matches
# Default: 'input/vm_call_stack.json'
```

### Issue: "Invalid JSON in trace file"

**Causes:**
1. Trace collection was interrupted
2. File corruption during transfer
3. Incomplete execution

**Solution:**
```bash
# Validate JSON
cat input/vm_call_stack.json | jq . > /dev/null

# If invalid, re-run the deobfuscator to collect new traces
```

### Issue: "Output is empty or incomplete"

**Checklist:**
1. Verify trace file contains function data
2. Check for errors during IR lifting
3. Ensure all dependencies are installed
4. Review console output for warnings

**Debug:**
```javascript
// Add logging to index.ts
console.log('Functions found:', functionTraceMap.size);
console.log('IR blocks:', ir.blocks.size);
```

### Issue: "Generated code has syntax errors"

**Possible Causes:**
1. Incomplete traces
2. Edge cases in lifting logic
3. Special characters in identifiers

**Solution:**
1. Run through a JavaScript validator
2. Check for malformed expressions
3. Report specific patterns that fail

## Advanced Usage

### Processing Specific Functions

To lift only specific functions:

```javascript
// Filter traces before lifting
const filteredTraces = new Map();
const targetFunctions = ['fn_43518_9', 'fn_72714_0'];

targetFunctions.forEach(fn => {
  if (functionTraceMap.has(fn)) {
    filteredTraces.set(fn, functionTraceMap.get(fn));
  }
});

const irLifter = new IntermediateRepresentationLifter(filteredTraces);
// Continue with lifting...
```

### Analyzing Control Flow

Access the IR for custom analysis:

```javascript
const ir = irLifter.lift();

// Examine blocks
ir.blocks.forEach((block, blockId) => {
  console.log(`Block ${blockId}:`);
  console.log(`  Operations: ${block.operations.length}`);
  console.log(`  Next blocks: ${block.next.join(', ')}`);
});
```

### Custom Post-Processing

Apply custom transformations:

```javascript
import traverse from '@babel/traverse';

const outputAst = jsLifter.lift();

// Custom transformation
traverse(outputAst, {
  Identifier(path) {
    // Rename stack variables
    if (path.node.name.startsWith('s')) {
      // Custom naming logic
    }
  }
});

const cleaner = new JavascriptBeautifier(outputAst);
// Continue...
```

## Performance Tips

1. **Process in Batches:**
   - Split large trace files
   - Process functions in groups
   - Merge outputs afterward

2. **Optimize Memory:**
   - Clear intermediate data structures
   - Use streaming for very large files
   - Monitor memory usage

3. **Parallelize:**
   - Process independent functions concurrently
   - Use worker threads for large datasets
